## 概要

既存の Apex クラスを変更したり、本番組織にカスタムオブジェクトを追加したりしたいとします。まず、スクラッチ組織でこれらの変更を行ってテストし、競合がないか確認してから、チームがアクセスできるように別の組織に変更をリリースします。本番環境にリリースする前の様々なテストフェーズで、スクラッチ組織や Sandbox などの異なる Salesforce 開発環境間で変更を移動するこの機能は、Salesforce 開発の鍵となります。これらのメタデータ操作を使用して、アプリケーションライフサイクル管理 (ALM) プロセスの一環として、ローカルの変更を組織にリリースします。競合検出が有効になっていると、組織内の他のユーザーの変更を誤って上書きしてしまう心配はありません。ローカルファイルとデフォルトの組織間の変更をいつでも簡単に表示して、変更を追跡できます。チームで作業している場合は、組織内の最新の変更をローカル の Salesforce プロジェクトに取得できます。

## ソースの取得

**SFDX: Retrieve Source from Org (SFDX: 組織からソースを取得)** コマンドを使用して、デフォルトの組織からローカルプロジェクトにメタデータを取り込みます。ソース追跡されない組織の場合、VS Code は組織への変更を自動的に追跡しないため、取得した変更を必ず追跡してください。組織からソースを取得すると、ソースファイルのローカルバージョンが上書きされます。

![組織からソースを取得](./images/retrieve-source-from-org.png)

マニフェスト、ソースファイル、ディレクトリ、またはフォルダーのソースを取得できます。

- マニフェスト
  - VS Code のエクスプローラーまたはエディタ上で、マニフェストファイルを右クリックし、 **SFDX: Retrieve Source in Manifest from Org** を選択します。
  - エディターでマニフェストファイルを開いた状態で、コマンドパレットを開き、**SFDX: Retrieve Source in Manifest from Org** を実行します。
- ソースファイルまたはディレクトリ
  - VS Code のエクスプローラで、ソースファイルまたはディレクトリを右クリックし、**SFDX: Retrieve Source from Org** を実行します。
  - エディタでソースファイルを開いた状態で、編集ペインを右クリックし、**SFDX: Retrieve This Source from Org** を選択します。
  - エディタでソースファイルを開いた状態で、コマンドパレットを開き、**SFDX: Retrieve This Source from Org** を実行します。

ソースを取得する項目を選択すると、ディレクトリ構造内の既存のネストされた項目のみが取得されます。たとえば、`classes` フォルダのソースを取得すると、**現在そのディレクトリに存在する** Apex クラスが取得されます。このコマンドは、組織内のすべての Apex クラスを取得するわけではなく、フォルダ内に存在するクラスのみを更新します。新しい Apex クラスを取得するには、そのクラス (またはすべての Apex クラス) を `package.xml` ファイルに追加し、マニフェストファイルを使用してソースを取得します。ターミナルを使用して `sf project retrieve start --metadata ApexClass:YourApexClass` を実行することもできます。

[組織ブラウザ](./ja/user-guide/development-models/#create-project-and-use-org-browser)を使用してソースを取得することもできます。

ソースを取得した後のプロジェクト構造は次のようになります。

```text
your-app
├── README.md
├── sfdx-project.json
├── .sfdx
├── .vscode
│   ├── extensions.json
│   └── settings.json
├── force-app
|   └── main
|       └── default
|           ├── aura
|           ├── classes
|           └── objects
└── manifest
    └── package.xml
```

## ソースのデプロイ

**SFDX: Deploy Source to Org (SFDX: 組織にソースをデプロイ)** コマンドを使用して、ローカルプロジェクトからデフォルトの組織にメタデータをデプロイします。コードの変更をデプロイすると、ソースファイルのローカルバージョンで組織のメタデータを上書きます。組織とローカルのメタデータの間で競合の検知を有効化できます。[競合検知](./ja/user-guide/detect-conflicts)を参照してください。

![組織にソースをデプロイ](./images/deploy-source-to-org.png)

マニフェスト、ソースファイル、ディレクトリ、またはフォルダーのソースをデプロイできます。

- マニフェスト
  - VS Code のエクスプローラーまたはエディタ上で、マニフェストファイルを右クリックし、 **SFDX: Deploy Source in Manifest from Org** を選択します。
  - エディターでマニフェストファイルを開いた状態で、コマンドパレットを開き、**SFDX: Deploy Source in Manifest from Org** を実行します。
- ソースファイルまたはディレクトリ
  - VS Code のエクスプローラで、単一または複数選択したソースファイルまたはディレクトリを右クリックし、**SFDX: Deploy Source from Org** を実行します。
  - エディタでソースファイルを開いた状態で、編集ペインを右クリックし、**SFDX: Deploy This Source from Org** を選択します。
  - エディタでソースファイルを開いた状態で、コマンドパレットを開き、**SFDX: Deploy This Source from Org** を実行します。

## ソースの差分

ソースの差分コマンドを使用すると、デフォルトの組織に対してメタデータ型の差分をとることができます。この機能を使用することで、ローカルのプロジェクトと組織内のメタデータとの間の変更をより簡単に視覚化することができます。
ファイルまたはフォルダを右クリックし、`SFDX: Diff File Against Org (SFDX: ファイルと組織の差分を表示)` または `SFDX: Diff File Against Org (SFDX: フォルダと組織の差分を表示)` を実行します。

![ソースの差分コマンド](./images/source_diff.png)

個々のファイルの差分を並べて見ることができます。もしファイルがローカルにも組織にも存在しない場合は、リストに表示されません。

## ソースの削除

プロジェクトと組織からソースを削除できます。

- VS Code のエクスプローラで、ソースファイルまたはディレクトリを右クリックして、**SFDX: Delete from Project and Org (SFDX: プロジェクトおよび組織から削除)** を選択します。
- エディターでソースファイルを開いた状態で、ファイルを右クリックし、**SFDX: Delete This from Project and Org (SFDX: このソースをプロジェクトと組織から削除)** を選択します。
- エディターでソースファイルを開いた状態で、コマンドパレットを開き、**SFDX: Delete This from Project and Org (SFDX: このソースをプロジェクトと組織から削除)** を実行します。

## コンポーネントの名称を変更

**SFDX Rename Component (SFDX: コンポーネントの名称を変更)** コマンドを使用して、コンポーネントとそれに関連付けられているすべてのファイル (LWC コンポーネントのテストファイルを含む) の名称を変更できます。このコマンドは、新しいコンポーネント名が必要な命名規則に従っていない場合、名称の変更を防止します。Lightning Web コンポーネントの場合、このコマンドは必要に応じて大文字と小文字を自動的に変更します。

プロジェクト内のコンポーネントの名称を変更しても、組織からコンポーネントは削除されません。組織内のコンポーネントの名称を変更するには、次の手順を実行します。

1. 組織にログインし、古い名称のコンポーネントを削除します。
2. プロジェクト内のコンポーネントの名称をします。
3. 更新された名称でコンポーネントをデプロイします。
